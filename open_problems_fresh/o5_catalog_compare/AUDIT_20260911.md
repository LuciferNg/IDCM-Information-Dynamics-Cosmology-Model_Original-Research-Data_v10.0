## 2. 發現（F1-F6）

### F1 — scripts/03_match_nodes.py: node 欄位 = 最遠節點（argmin-dots bug）⚠️ 數據標籤
`nearest_node()` 回傳 `int(np.argmin(dots))`（最小 cos = 最遠），正確應係
`argmin(distance)`（最近）。`match_results.json` 內全部 35 個 `node` 欄位
（以及 03 打印表）因此係**最遠**節點索引；`nearest_deg` 距離欄位正確。
**影響評估：零** — 所有結論（命中數、距離、p-value、交叉尺度）都用距離，
冇任何文檔引用 match_results 嘅 node 標籤（NN_results 嘅「節點 0」係自己
正確標識）。06/05/13 用 `argmin(d)` 正確。對照：cross_scale_match.json
嘅 node 欄位全部正確（J3 check PASS）。

### F2 — scripts/02_smica_catalog.py: 潛在 NameError（BASE_DIR 未定義）
第 45 行 `CACHE5 = os.path.join(BASE_DIR, ...)` 喺檔案內冇定義 BASE_DIR →
現存版本無法獨立執行（重跑時由 runner 注入）。08-17 重跑當時版本冇此 bug
（log 顯示正常完成 240s）；12:13 編輯（cache 檔名 5.0 統一修正）時引入。
**不影響已記錄結果**（smica_catalog.json 由 11:37 嘅正確版本產生，內容已驗證）。
建議（唔執行，屬未來維護）：定義 BASE_DIR = data/smooth_cache 或改用
`__file__` 相對路徑。

### F3 — smooth cache 為 float32 儲存（精度註記，非錯誤）
現存 `data/smooth_cache/smica2_smooth*.fits` 全部 float32。獨立測試：
float32 cache vs float64 in-memory 重平滑（remove_dipole + 同 sigma）喺
63 個採樣點（60 節點 + F₆/F₇/冷斑）**完全一致（max |Δ| = 0.000 μK）** —
cache 忠實。08-17 11:33-12:04 嘅運行用 in-memory float64 → 本次重跑用
float32 cache → 目錄 amp 值有 ≤3e-6 μK 級差異（文檔引述 0.1 μK 精度不受影響）。
