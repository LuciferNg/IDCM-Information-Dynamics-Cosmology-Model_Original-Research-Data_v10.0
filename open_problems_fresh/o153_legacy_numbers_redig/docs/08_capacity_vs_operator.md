## 1. 容量語言 vs 算子語言

docs/07 用「算子」語言：±2 = ±γ₄₄ 切換（42 = N_d⁻, 46 = N_d⁺）。
用戶提出「容量」語言：世界/觀察者係**容量賬戶**，唔係算子。

| 量 | 值 | 身份 |
|:---|:--:|:-----|
| 世界容量 Σγ_even | **90** | s0+s2 = 46+44 |
| 觀察者容量 Σγ_odd | **88** | s1+s3 |
| 鏈容量 | **176** | B·N_d = 4×44 = 88 modes×2 = 172+4（43對偶對×B + γ₈₈） |
| 譜總和 | **178** | 176 + μ² = 容量 + 勢差 |
| 勢差 Δ | **2** | 90−88 = μ² = γ₄₄（世界−觀察者） |
| 殘差 | **4** | B = 2μ² = γ₈₈ = 46−42（家族 gap） |

## 2. 用戶框架逐點驗證

### 2.1 「世界90+觀察者88=176」 — 🔴 精確修正

90 + 88 = **178**，唔係 176。但用戶直覺有結構核心：
```
178 = 176 + 2 = B·N_d + μ²     (C3b ✅)
90 + 88 − μ² = 176             (C3c ✅: 扣勢差後先係鏈容量)
```
即係話：**世界+觀察者嘅總譜和 = 鏈容量 + 勢差**。勢差 2 唔係容量嘅一部分 — 佢係「額外」嘅，用嚟推動能量流動。

### 2.2 「實際殘差應該4」 — 🟢 精確位置確立

「殘差」= 4 有三個互相一致嘅身份（全部 EXACT）:
```
4 = B        (容量單位 = 2μ²)          (C5a ✅)
4 = γ₈₈      (Nyquist mode)             (C5b ✅)
4 = N_d⁺−N_d⁻ = 46−42 (世界自我−觀察者側) (C5c ✅)
4 = 2×(90−88) = 2×勢差                    (C5d ✅)
```

**語意修正**: docs/05 原本叫 42「殘差觀察者」— 用戶框架揭示真正嘅「殘差」係 **4 = B = 家族 gap**（46−42），而 42 本身係觀察者側維度（N_d⁻）。殘差 = 2μ² = 雙勢差 = 容量單位。

### 2.3 「能量要有勢差才能動」 — 🟢 beat 機制精確對應

| 物理原則 | 結構對應 | 驗證 |
|:---------|:---------|:----:|
| 冇勢差 = 冇能量流動 | beat(44,44) = 0（同 mode 冇拍頻） | C8a ✅ |
| 有勢差 = 能量流動 | beat(44,45) = 0.050 > 0 | C8b ✅ |
| 勢差越大 → 能量流動越強 | beat(44,46) > beat(44,45) > beat(44,44) | C8e ✅ |
| 每步消耗 = 勢差本身 | 88 ops × μ² = 176 = B·N_d（O41 交叉） | C9a/b ✅ |
| 拍頻交換對稱 | beat(a,b) = beat(b,a) | C8c ✅ |

**核心**: beat 係能量交換（拍頻），佢嘅強度 ∝ sin(勢差π/176)·v_g(中心) — **勢差係能量流動嘅燃料**，每步操作正好消耗 1 個勢差單位（2），88 步 = 176 = 鏈容量。呢個係 O41 讀↔寫循環嘅容量語言表述。
