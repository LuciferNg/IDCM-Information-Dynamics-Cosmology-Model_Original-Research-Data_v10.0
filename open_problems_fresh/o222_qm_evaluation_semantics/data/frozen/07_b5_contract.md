## §2 D5-B 機器（機械定義，全部由 §1 導出）

```
狀態: 世界 G ∈ 2I (120) · ledger L · 剩餘預算 B_rem (初始 123/2)
read(G, ctx):
   若 L 頂 ctx 相同:  回 memo 值, 成本 0, 狀態不變            [I8：memo 命中唔寫世界、唔花預算]
   否則:              v = sign(u_ctx·(G n̂))                  [I9]
                      push (ctx, v, G);  G ← G·h(ctx)          [A2 §1]
                      B_rem ← B_rem − 123/88                   [I4]
rollback(): pop; G ← 記錄態;  B_rem 唔回退（讀已經發生）        [D5：回滾唔退預算]
terminal:  若 B_rem < E_min = 123/176 ⟹ 不能再讀 ⟹ pass 終止
```

**兩個直接推論（寫死為 D5-B1/B2，本輪必須精確驗算）**
- **D5-B1（讀數上限）**：`max reads/pass = (123/2) / (123/176) = 88` **EXACT**。
- **D5-B2（pass 規模）**：每對 2 次非 memo 讀 ⟹ `max pairs/pass = 44`；
  A2 之指定 pass（3844 對 × 2 = **7688 reads**）超支 `7688/88 = 961/11 ≈ 87.36` 倍 ⟹ **不可行**。

**D5-B3（pass 之實際內容）**：因次序凍結（I10），可行 pass = **凍結次序之頭 44 對**（88 讀，恰好用盡預算）。
（亦報告其他窗口形式，但**主判準**用凍結次序之前綴 —— 理由：次序係凍結輸入，唔准為結果而改。）

## §4 `τ_deco` 身份（本合約之**主推導目標**）

**主張**：耗盡預算之 pass 之時長恰為 `2·tick = τ_deco`。

**推導（兩因子獨立）**：
```
max reads/pass = I1/I3 = (123/2)/(123/176) = 88            ← 預算帳目（O41）
讀率           = 44 reads/tick = N_d                      ← 執行層（O126：讀 = 寫 = N_d）
⟹ pass 時長    = 88/44 = 2 ticks = τ_deco = 1.9235228 Gyr  ← 與登記值 1.9235227 相符
```
**誠實附註**：此推導**唔**用「數字吻合」——兩因子（88 與 44）各自獨立凍結於唔同 O，相乘關係係推導結果；
但仍須檢查：(a) 44 reads/tick 之「tick」定義是否與 I6 同一個 tick；(b) 88 是否**恰好**（而非近似）等於 I1/I3。
兩者皆為精確算術，於凍結輪驗算。

- **G2（逐模頻率 f(n)）**：O206 `01_problem_record` 已標 🔴；本輪**假設** ω_n = μ²（I4，已凍結 44/44 EXACT）
