## 2. ★ 關鍵發現：B 方案嘅「頂」291.5 未鎖定

```
μ_ℓ = φ^(291.5−ℓ)
291.5 = N_d·L = 44 × 53/8 = 583/2 = (11×53)/2
53/8 = 6.625 — RAG 查無出處! 53 = 質數 ∉ Lucas/Fib/生成集
583 = 11×53 (11 = φ⁵−φ⁻⁵ 結構數 ✓, 53 = ? ✗)
```

**⟹ K_tree 頂部指數 291.5 本身未有結構鎖定** — 同 M₀ 一樣嘅病：
「頂部標量未有結構」。scripts/02 直接當基礎常數用，冇推導。

## 4. N_O38 喺樹入面邊個位置？

```
log_φ N_O38 = 192.6225  ⟹ ℓ = 291.5 − 192.62 = 98.88（超出 33 層樹!）
⟹ N_O38 唔係 K_tree μ_ℓ 譜嘅單層標度
```

**指數層線索**：192.6225 ≈ 291.5 − 99 = 192.5（dev 6.4e−4）；**99 = 3M = 3×33**
（3 = 世代數, M = 33 層）⟹ 候選結構：N_O38 ≈ μ₀·φ^(−3M) = N_IDCM·φ^(−99)
但數值層 dev 13% — 唔過閘，只做線索唔升格。

## 5. 判決：正確方向 = A（中央不動點向外）

1. **B 方案（頂底分級）嘅「頂」未鎖定**（291.5 = 44×53/8, 53 冇身份）
   ⟹ B 方案唔可以作為標度定義源頭 — 頂部標量本身又係 fit 嘅候選
2. **A 方案（中央不動點向外）嘅中央已鎖定**：
   O213 L→c（291/291）、O212 錨（唯一測量）、中樞 γ_44 軸（scripts/27）
3. ⟹ **正確構造：先有中央不動點（c / ω_ring / γ_44），向外擴展生成標度層；
   頂底標量（B）只係結果描述，唔係起因**
4. μ₀ ≈ N_IDCM 線索指向：樹頂 = 總節拍數（O212），呢個係「頂」嘅正當鎖定來源
